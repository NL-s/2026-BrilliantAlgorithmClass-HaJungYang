# 3주차 — Dynamic Programming

다이나믹 프로그래밍(DP)에 처음 발을 들이면 누구나 비슷한 경험을 한다. "개념은 이해했는데… 막상 문제 앞에서 아무것도 안 떠오른다." 이건 네가 부족한 게 아니다. DP는 단순 암기로는 절대 늘지 않고, **점화식을 직접 세워 보는 반복 훈련**만이 실력을 올려 준다. 같은 문제를 5번 풀어서 점화식이 손에 익기 전까지는 "이해했다"고 착각하지 마라 — 이건 조언이 아니라 진심이다.

DP가 어렵게 느껴지는 이유는 두 가지다. 첫째, **재귀 사고**와 **반복문 사고**를 동시에 요구한다. 문제를 작은 문제로 쪼개는 시각(재귀)과, 작은 것부터 테이블을 채워 올라가는 시각(반복문)을 모두 가져야 한다. 둘째, **"어떤 정보를 상태로 정의하느냐"** 가 답의 절반이다. 상태 정의를 잘못 잡으면 점화식 자체가 성립하지 않는다.

이번 주 목표는 단순하다: 피보나치 → 계단 오르기 → LIS → 배낭 → LCS 순서로, **점화식 도출 4단계**를 반복 적용하며 DP 근육을 만드는 것이다. 예제마다 C++ 코드를 직접 돌려보고, 테이블이 채워지는 과정을 눈으로 따라가 보자.

## 1. DP 마인드셋

### DP란 무엇인가?

DP는 크게 두 가지 조건을 만족하는 문제에 쓰인다.

| 조건 | 설명 |
|------|------|
| **겹치는 부분 문제 (Overlapping Subproblems)** | 큰 문제를 풀 때 **같은 작은 문제가 여러 번 반복**해서 등장한다. |
| **최적 부분 구조 (Optimal Substructure)** | 작은 문제들의 최적해를 조합하면 **큰 문제의 최적해**가 된다. |

이 두 조건을 만족하면 이미 계산한 결과를 **캐시(배열)**에 저장해 두고 재사용한다. 이것이 DP의 전부다.

### 점화식이란?

점화식은 `dp[i]` (또는 `dp[i][j]`)를 **이전 상태들로 표현**하는 수식이다.

```
dp[i] = (dp[i-1] 또는 dp[i-2] 또는 ... 를 이용한 식)
```

점화식을 세운다는 것은, "i번째 답을 구하려면 그 전 단계에서 어떤 선택이 있었는가?" 를 정확히 규명하는 작업이다.

### 상태(State) 정의의 중요성

**상태**는 `dp[i]`가 "무엇을 의미하는지"다. 상태 정의가 곧 점화식의 설계도다.

- `dp[i]` = "i번째 계단까지 오는 방법의 수"  → 계단 오르기 문제
- `dp[i]` = "arr[i]를 마지막 원소로 하는 LIS의 길이"  → LIS 문제
- `dp[i][w]` = "물건 0~(i-1)까지 (총 i개) 고려, 무게 한도 w일 때 최대 가치 (dp[0][w]=0)"  → 배낭 문제

상태 정의가 흔들리면 점화식도 흔들린다. **첫 번째 질문은 항상 "dp[i]가 정확히 무엇을 뜻하는가?"** 여야 한다.

---

### 점화식 도출 4단계 체크리스트

> 모든 DP 문제에서 이 4단계를 순서대로 밟아라. 이 습관이 생기기 전까지는 절대 코딩부터 시작하지 마라.

```
[ ] 1단계 — 상태 정의
       dp[i] (또는 dp[i][j])가 정확히 무엇을 의미하는지 한 문장으로 적는다.
       예) dp[i] = "인덱스 i까지 고려했을 때 LIS의 최대 길이"

[ ] 2단계 — 답이 어디에 있는지
       최종 답이 dp[n]인지, max(dp[0..n])인지, dp[n][W]인지 파악한다.
       예) 답 = max(dp[0], dp[1], ..., dp[n-1])

[ ] 3단계 — 점화식
       dp[i]를 dp[i-1], dp[i-2], ..., dp[j] (j < i) 등으로 표현한다.
       예) dp[i] = max(dp[j] + 1)  (j < i이고 arr[j] < arr[i]인 모든 j)

[ ] 4단계 — 초기값 & 계산 순서
       베이스 케이스(dp[0], dp[1] 등)를 설정하고,
       작은 인덱스부터 큰 인덱스 순서로 채운다.
       예) dp[i] = 1 (모든 i에 대해 초기값)
```

## 2. Top-Down — 메모이제이션 (피보나치)

> **30초 요약**: 재귀 함수에 **캐시 배열**을 달아서, 이미 계산한 값은 다시 계산하지 않는다. 코드 구조는 재귀 그대로, 성능은 DP.

### 일상 비유

시험 준비할 때 이미 풀어 본 문제는 풀이를 노트에 적어 두고 다시 볼 때 그냥 노트를 확인한다. 처음 보는 문제만 새로 풀면 된다. 메모이제이션이 바로 이 "노트"다.

### 시각화 — 브루트 포스 vs 메모이제이션

**브루트 포스 (fib(5) 호출 트리)**:
```
                          fib(5)
                        /        \
                  fib(4)          fib(3)     <- fib(3) 중복!
                 /      \         /     \
           fib(3)      fib(2)  fib(2)  fib(1) <- fib(2) 3곳 등장!
           /    \       /   \   /   \
       fib(2) fib(1) fib(1) fib(0) fib(1) fib(0)
       /    \
   fib(1) fib(0)

총 호출 횟수: 15회 (n이 커질수록 2^n에 가까워짐)
```

**메모이제이션 (memo 배열 활용)**:
```
fib(5) 호출
  → fib(4) 호출
      → fib(3) 호출
          → fib(2) 호출 → memo[2] = 1 저장
          → fib(1) → 1
          → memo[3] = 2 저장
      → fib(2) → memo[2] = 1 (캐시 히트!)
      → memo[4] = 3 저장
  → fib(3) → memo[3] = 2 (캐시 히트!)
  → memo[5] = 5

총 호출 횟수: 9회 (각 n당 딱 한 번만 계산)
```

### 점화식

```
dp[n] = dp[n-1] + dp[n-2]

초기값:
  dp[0] = 0
  dp[1] = 1
```

### 동작 원리 — 단계별

1. `fib(n)` 호출 시 `memo[n]`이 이미 채워져 있으면 즉시 반환.
2. 없으면 `fib(n-1) + fib(n-2)` 재귀 계산 후 `memo[n]`에 저장.
3. 베이스 케이스: `n == 0`이면 0, `n == 1`이면 1 반환.

### C++ 코드

```cpp
// g++ -std=c++17 -Wall -o wk3_1.bin wk3_1.cpp
#include <bits/stdc++.h>
using namespace std;

// ───── 브루트 포스 피보나치 (O(2^n)) ─────
long long fib_brute(int n) {
    if (n <= 1) return n;
    return fib_brute(n - 1) + fib_brute(n - 2);  // 같은 계산 반복!
}

// ───── 메모이제이션 피보나치 (O(n)) ─────
const int MAXN = 100;
long long memo[MAXN];  // 전역 배열: 기본값 0으로 초기화됨

long long fib_memo(int n) {
    if (n <= 1) return n;               // 베이스 케이스
    if (memo[n] != 0) return memo[n];   // 캐시 히트: 이미 계산한 값 반환
    memo[n] = fib_memo(n - 1) + fib_memo(n - 2);  // 계산 후 저장
    return memo[n];
}

int main() {
    // 브루트 포스 vs 메모이제이션 시간 비교
    int n = 42;  // 42 정도면 브루트 포스가 체감상 느려짐

    // 브루트 포스 시간 측정
    auto t1 = chrono::high_resolution_clock::now();
    long long res_brute = fib_brute(n);
    auto t2 = chrono::high_resolution_clock::now();
    long long ms_brute = chrono::duration_cast<chrono::milliseconds>(t2 - t1).count();

    // 메모이제이션 시간 측정
    auto t3 = chrono::high_resolution_clock::now();
    long long res_memo = fib_memo(n);
    auto t4 = chrono::high_resolution_clock::now();
    long long ms_memo = chrono::duration_cast<chrono::milliseconds>(t4 - t3).count();

    cout << "=== 피보나치(" << n << ") 계산 결과 ===" << endl;
    cout << "브루트 포스 결과: " << res_brute << " (" << ms_brute << "ms)" << endl;
    cout << "메모이제이션 결과: " << res_memo << " (" << ms_memo << "ms)" << endl;

    // fib(1) ~ fib(10) 출력
    cout << "\n피보나치 수열 (1~10):" << endl;
    for (int i = 1; i <= 10; i++) {
        cout << "fib(" << i << ") = " << fib_memo(i) << endl;
    }
    return 0;
}
```

### 시간/공간 복잡도

| 방식 | 시간 복잡도 | 공간 복잡도 |
|------|------------|------------|
| 브루트 포스 | O(2^n) | O(n) 스택 |
| 메모이제이션 | O(n) | O(n) 메모 배열 + O(n) 스택 |

### 자주 하는 실수

- **캐시 초기화 주의**: 일반적으로 0이 유효한 답인 DP에서는 `memo`를 `-1`로 초기화하고 `!= -1` 조건으로 체크하는 게 안전하다. 여기서는 `if (n <= 1) return n;` 베이스 케이스가 먼저 리턴하므로 `memo[0]`, `memo[1]`은 실제로 읽히지 않고, `n >= 2`의 피보나치 값은 모두 1 이상이라 `!= 0` 판별이 정확히 동작한다. 실제 문제는 없지만, 다른 DP에서 0이 유효한 답이 될 수 있을 때는 반드시 `-1` 초기화 패턴을 쓸 것.
- **전역 배열 초기화 순서 착각**: 전역 배열은 0으로 자동 초기화되지만, 지역 배열은 쓰레기값이 들어 있다. 지역 배열 사용 시 반드시 `fill` 또는 `memset` 호출.
- **스택 오버플로우**: `n`이 매우 크면 재귀 깊이 초과. Bottom-Up으로 전환하거나, 재귀 깊이 제한을 늘려야 한다.

## 3. Bottom-Up — 타뷸레이션 (계단 오르기)

> **30초 요약**: 재귀 없이 **작은 인덱스부터 배열을 직접 채워 올라간다**. 스택 오버플로우 걱정 없이 대용량 입력을 처리할 수 있다.

### 일상 비유

레고를 조립할 때, 완성품을 상상하면서 역방향으로 뜯어내지 않는다. 바닥 조각부터 하나씩 쌓아 올린다. 타뷸레이션은 이 "바닥부터 쌓기" 방식이다.

### 문제 설명

> n개의 계단이 있다. 한 번에 1칸 또는 2칸씩 올라갈 수 있다. n번째 계단에 도달하는 방법의 수는?

### 시각화 — DP 테이블 채우기

계단이 5개일 때 (`n = 5`):

```
초기값 설정:
  dp[1] = 1   (1칸짜리: [1])
  dp[2] = 2   (2칸짜리: [1+1], [2])

점화식 적용: dp[i] = dp[i-1] + dp[i-2]

  i=3: dp[3] = dp[2] + dp[1] = 2 + 1 = 3
  i=4: dp[4] = dp[3] + dp[2] = 3 + 2 = 5
  i=5: dp[5] = dp[4] + dp[3] = 5 + 3 = 8

DP 테이블:
┌─────┬───┬───┬───┬───┬───┐
│  i  │ 1 │ 2 │ 3 │ 4 │ 5 │
├─────┼───┼───┼───┼───┼───┤
│dp[i]│ 1 │ 2 │ 3 │ 5 │ 8 │
└─────┴───┴───┴───┴───┴───┘
```

`dp[5] = 8`가지 방법:
- [1,1,1,1,1], [1,1,1,2], [1,1,2,1], [1,2,1,1], [2,1,1,1]
- [1,2,2], [2,1,2], [2,2,1] → 총 8가지

### 점화식

```
dp[i] = dp[i-1] + dp[i-2]
        ↑              ↑
  i-1번째에서        i-2번째에서
  1칸 점프           2칸 점프

초기값:
  dp[1] = 1
  dp[2] = 2
```

### 동작 원리 — 단계별

1. `dp[1] = 1`, `dp[2] = 2` 로 베이스 케이스 설정.
2. `i = 3`부터 `i = n`까지 순서대로 `dp[i] = dp[i-1] + dp[i-2]` 계산.
3. `dp[n]`이 최종 답.

왜 `dp[i] = dp[i-1] + dp[i-2]` 인가? i번째 계단에 오는 직전 상황이 딱 두 가지뿐이기 때문이다:
- `i-1`번째 계단에서 **1칸** 오기 → `dp[i-1]` 가지
- `i-2`번째 계단에서 **2칸** 오기 → `dp[i-2]` 가지

두 경우는 겹치지 않으므로 더하면 된다.

### C++ 코드

```cpp
// g++ -std=c++17 -Wall -o wk3_2.bin wk3_2.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n = 10;  // 계단 수 (데모용 하드코딩)

    // ── n=0 이하 경계 처리 (n=0이면 아무 계단도 없으므로 방법 0) ──
    if (n <= 0) { cout << "계단 수 0 이하: 방법 0" << endl; return 0; }

    // dp[i] = i번째 계단에 도달하는 방법의 수
    vector<long long> dp(n + 1, 0);

    // ── 베이스 케이스 ──
    dp[1] = 1;  // 계단 1: [1]
    if (n >= 2) dp[2] = 2;  // 계단 2: [1+1], [2]

    // ── 점화식 적용 ──
    for (int i = 3; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];  // i-1에서 1칸 + i-2에서 2칸
    }

    // ── 결과 출력 ──
    cout << "=== 계단 오르기 (1칸/2칸 점프) ===" << endl;
    for (int i = 1; i <= n; i++) {
        cout << "dp[" << i << "] = " << dp[i] << "가지" << endl;
    }
    cout << "\n계단 " << n << "개: " << dp[n] << "가지 방법" << endl;

    return 0;
}
```

### 시간/공간 복잡도

| 항목 | 복잡도 |
|------|--------|
| 시간 | O(n) |
| 공간 | O(n) (배열) / O(1) 로 줄일 수 있음 (변수 2개만 유지) |

**공간 O(1) 최적화**: `dp[i]`는 `dp[i-1]`과 `dp[i-2]`만 필요하므로 변수 두 개로 롤링 가능.

### 자주 하는 실수

- **`dp[0]` 처리 실수**: n=1일 때 `dp[1-1] = dp[0]`을 참조하면 쓰레기값. `n >= 2` 조건 분기 또는 `dp[0] = 1`로 초기화해서 방어.
- **배열 크기를 `n`으로 잡으면 `dp[n]` 인덱스 초과**: `vector<long long> dp(n + 1)` 처럼 반드시 `n+1` 크기로 선언.
- **점화식 방향 혼동**: `dp[i]`를 "i에서 출발하는 경우의 수"로 정의하면 반대로 채워야 한다. 방향을 헷갈리지 않도록 상태 정의를 먼저 명확히 할 것.

### 연습문제

1. **[BOJ 2579] 계단 오르기** — 연속 3칸 금지 조건 추가 버전. 상태 정의를 `dp[i][0/1]`로 확장.
2. **[BOJ 11726] 2×n 타일링** — 1×2 또는 2×1 타일로 2×n 직사각형 채우기. 점화식 구조 동일.

## 4. 1D DP — LIS (Longest Increasing Subsequence)

> **30초 요약**: 수열에서 **값이 순서대로 증가하는 가장 긴 부분 수열**의 길이를 구한다. O(n²) DP로 시작해서 감을 잡자.

### 일상 비유

키 순서대로 줄 세우기를 생각해 보자. 여러 명이 무작위 순서로 서 있는데, 앞에서 뒤로 가면서 "이 사람보다 큰 사람"만 골라내면 점점 커지는 키 순서가 된다. 그 중 가장 긴 열이 LIS다.

### 시각화 — DP 테이블

배열: `arr = [3, 1, 4, 1, 5, 9, 2, 6]`

```
인덱스:   0   1   2   3   4   5   6   7
arr:     [3,  1,  4,  1,  5,  9,  2,  6]
dp:       1   1   ?   ?   ?   ?   ?   ?

i=2, arr[2]=4:
  j=0: arr[0]=3 < 4 → dp[2] = max(dp[2], dp[0]+1) = max(1,2) = 2
  j=1: arr[1]=1 < 4 → dp[2] = max(2, dp[1]+1) = max(2,2) = 2
  → dp[2] = 2

i=3, arr[3]=1:
  j=0: arr[0]=3 >= 1 → 스킵
  j=1: arr[1]=1 >= 1 → 스킵
  j=2: arr[2]=4 >= 1 → 스킵
  → dp[3] = 1  (자기 자신만)

i=4, arr[4]=5:
  j=0: 3<5 → dp[4]=max(1, dp[0]+1)=2
  j=1: 1<5 → dp[4]=max(2, dp[1]+1)=2
  j=2: 4<5 → dp[4]=max(2, dp[2]+1)=3
  j=3: 1<5 → dp[4]=max(3, dp[3]+1)=3
  → dp[4] = 3

(계속...)

최종 dp:  [1,  1,  2,  1,  3,  4,  2,  4]
                                          ↑
                              답 = max(dp) = 4
```

LIS 중 하나: `[1, 4, 5, 9]` 또는 `[1, 4, 5, 6]` (길이 4)

### 점화식

```
dp[i] = "arr[i]를 마지막 원소로 하는 LIS의 최대 길이"

dp[i] = max(dp[j] + 1)   (단, 0 <= j < i 이고 arr[j] < arr[i])
       만약 그런 j가 없으면 dp[i] = 1

초기값: dp[i] = 1 (모든 i에 대해, 자기 자신만으로 이루어진 길이 1짜리 수열)

최종 답 = max(dp[0], dp[1], ..., dp[n-1])
```

### 동작 원리 — 단계별

1. `dp` 배열 전체를 1로 초기화 (각 원소 자신이 길이 1짜리 LIS).
2. 바깥 루프 `i = 1 ~ n-1`: "arr[i]를 LIS의 마지막 원소로 넣는다면?"
3. 안쪽 루프 `j = 0 ~ i-1`: `arr[j] < arr[i]`인 j를 찾아 `dp[i] = max(dp[i], dp[j]+1)` 갱신.
4. 전체 dp 중 최댓값이 LIS 길이.

### C++ 코드

```cpp
// g++ -std=c++17 -Wall -o wk3_3.bin wk3_3.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 데모 입력: LIS 길이 4 (예: [1,4,5,9] 또는 [1,4,5,6])
    vector<int> arr = {3, 1, 4, 1, 5, 9, 2, 6};
    int n = arr.size();

    // dp[i] = arr[i]를 마지막으로 하는 LIS의 최대 길이
    vector<int> dp(n, 1);  // 초기값 전부 1

    for (int i = 1; i < n; i++) {
        for (int j = 0; j < i; j++) {
            if (arr[j] < arr[i]) {  // arr[j]가 arr[i]보다 작아야 증가 수열 성립
                dp[i] = max(dp[i], dp[j] + 1);
            }
        }
    }

    // 최댓값 찾기
    int ans = *max_element(dp.begin(), dp.end());

    // 결과 출력
    cout << "=== LIS (O(n^2) DP) ===" << endl;
    cout << "배열: ";
    for (int x : arr) cout << x << " ";
    cout << endl;

    cout << "dp:   ";
    for (int x : dp) cout << x << " ";
    cout << endl;

    cout << "LIS 길이: " << ans << endl;

    // LIS 실제 경로 역추적 (bonus)
    int maxIdx = max_element(dp.begin(), dp.end()) - dp.begin();
    vector<int> lis;
    int curLen = dp[maxIdx];
    lis.push_back(arr[maxIdx]);
    for (int i = maxIdx - 1; i >= 0 && curLen > 1; i--) {
        if (dp[i] == curLen - 1 && arr[i] < arr[maxIdx]) {
            lis.push_back(arr[i]);
            maxIdx = i;
            curLen--;
        }
    }
    reverse(lis.begin(), lis.end());
    cout << "LIS 경로: ";
    for (int x : lis) cout << x << " ";
    cout << endl;

    return 0;
}
```

### 시간/공간 복잡도

| 항목 | O(n²) DP | O(n log n) 이분탐색 버전 |
|------|----------|------------------------|
| 시간 | O(n²) | O(n log n) |
| 공간 | O(n) | O(n) |

> O(n²)를 완전히 이해한 뒤에 아래 O(n log n) 버전에 도전하자.

### 심화 — O(N log N) LIS (patience sorting / tails 배열)

**핵심 아이디어**: `tails[k]` = 길이 k+1짜리 증가 수열의 **마지막 원소 중 가장 작은 값**을 유지한다.
새 원소 `x`가 들어오면 `lower_bound`로 `tails`에서 x 이상인 첫 위치를 찾아 교체한다.
`tails`의 길이가 LIS 길이다. (실제 수열이 아닌 보조 구조임에 주의!)

```cpp
// g++ -std=c++17 -Wall -o wk3_3b.bin wk3_3b.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> arr = {3, 1, 4, 1, 5, 9, 2, 6};  // 데모 입력
    int n = arr.size();

    // tails[k] = 현재까지 발견한 길이 (k+1)짜리 증가 수열의
    //            마지막 원소 중 최솟값 (단조 증가 배열 유지)
    vector<int> tails;

    for (int i = 0; i < n; i++) {
        // arr[i] 이상인 첫 번째 위치를 이분 탐색
        // (strictly increasing: lower_bound → arr[i] 이상인 위치 교체)
        auto it = lower_bound(tails.begin(), tails.end(), arr[i]);

        if (it == tails.end()) {
            // arr[i]가 현재 tails의 모든 원소보다 크다 → LIS 길이 1 증가
            tails.push_back(arr[i]);
        } else {
            // arr[i]로 해당 위치를 교체 → tails를 가능한 한 작게 유지
            *it = arr[i];
        }

        // 디버그: 각 단계에서 tails 상태 출력
        cout << "arr[" << i << "]=" << arr[i] << "  tails: ";
        for (int v : tails) cout << v << " ";
        cout << "\n";
    }

    cout << "LIS 길이: " << tails.size() << "\n";
    // 주의: tails 배열 자체가 LIS 수열은 아님!
    // 실제 LIS 경로 복원이 필요하면 parent 배열을 별도로 관리해야 한다.
    return 0;
}
```

**예상 출력**:
```
arr[0]=3  tails: 3
arr[1]=1  tails: 1
arr[2]=4  tails: 1 4
arr[3]=1  tails: 1 4
arr[4]=5  tails: 1 4 5
arr[5]=9  tails: 1 4 5 9
arr[6]=2  tails: 1 2 5 9
arr[7]=6  tails: 1 2 5 6
LIS 길이: 4
```

### 자주 하는 실수

- **`dp[i]`를 0으로 초기화**: LIS는 최소 자기 자신 하나이므로 초기값은 **반드시 1**. 0으로 초기화하면 답이 하나씩 줄어든다.
- **`arr[j] <= arr[i]` 조건 사용**: 같은 값을 허용하면 "순증가(strictly increasing)"가 아니라 "비감소" LIS가 된다. 문제 요구사항을 정확히 읽을 것.
- **최종 답을 `dp[n-1]`로 착각**: LIS는 반드시 마지막 원소에서 끝나지 않는다. 반드시 `max(dp[0..n-1])`로 구해야 한다.

### 연습문제

1. **[BOJ 11053] 가장 긴 증가하는 부분 수열** — 기본 LIS 문제. O(n²) DP로 AC 가능.
2. **[BOJ 14002] 가장 긴 증가하는 부분 수열 4** — LIS 길이 + 실제 경로 출력. 역추적 연습.

## 5. 2D DP — 0/1 배낭 (Knapsack)

> **30초 요약**: N개 물건 중 **넣을지/말지** 선택하며, 무게 한도 W 안에서 **가치 합을 최대화**한다. 2D DP 테이블의 전형적인 예.

### 일상 비유

소풍 가방에 물건을 넣는 상황을 상상하자. 가방은 최대 10kg까지 들 수 있고, 물건마다 무게와 즐거움 점수가 있다. 즐거움 합계를 최대화하면서 가방이 터지지 않게 싸야 한다. 각 물건은 넣거나(1) 말거나(0), 두 가지 선택뿐 — 그래서 "0/1 배낭"이다.

### 시각화 — DP 테이블 채우기

물건 3개, 무게 한도 W=6:

```
물건:  번호  무게  가치
       0     2     3
       1     3     4
       2     4     5

dp[i][w] = "물건 0~(i-1)까지 고려하고, 무게 한도가 w일 때 최대 가치"
           (1-indexed 물건, 0-indexed 테이블)

     w=  0  1  2  3  4  5  6
i=0     [0, 0, 0, 0, 0, 0, 0]  ← 물건 없을 때 모두 0
i=1     [0, 0, 3, 3, 3, 3, 3]  ← 물건0(무게2,가치3) 추가
i=2     [0, 0, 3, 4, 4, 7, 7]  ← 물건1(무게3,가치4) 추가
i=3     [0, 0, 3, 4, 5, 7, 8]  ← 물건2(무게4,가치5) 추가

채우는 방법 (i=2, w=5 예시):
  물건1(무게3, 가치4) 넣을 수 있음 (3 <= 5)
  → 안 넣기: dp[1][5] = 3
  → 넣기:    dp[1][5-3] + 4 = dp[1][2] + 4 = 3 + 4 = 7
  → max(3, 7) = 7

최종 답: dp[3][6] = 8
```

### 점화식

```
dp[i][w] = "물건 0~(i-1)까지 고려, 무게 한도 w에서 최대 가치"

if (weight[i-1] > w):   // 물건 i-1을 못 넣는 경우
    dp[i][w] = dp[i-1][w]
else:                   // 넣거나 안 넣거나 선택
    dp[i][w] = max(
        dp[i-1][w],                          // 안 넣는 경우
        dp[i-1][w - weight[i-1]] + value[i-1]  // 넣는 경우
    )

초기값:
  dp[0][w] = 0  (물건이 없으면 가치 0)
  dp[i][0] = 0  (무게 한도 0이면 아무것도 못 넣음)
```

### 동작 원리 — 단계별

1. (N+1) × (W+1) 크기의 dp 테이블을 0으로 초기화.
2. `i = 1`부터 `N`까지 (물건 번호), `w = 0`부터 `W`까지 (무게 한도) 이중 루프.
3. 각 칸에서: "이 물건을 넣을 수 있는가?" → 못 넣으면 위 행 그대로, 넣을 수 있으면 `max(안 넣기, 넣기)` 선택.
4. `dp[N][W]`가 최종 답.

### C++ 코드

```cpp
// g++ -std=c++17 -Wall -o wk3_4.bin wk3_4.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 데모 입력: 물건 4개, 무게 한도 7
    int N = 4;  // 물건 수
    int W = 7;  // 무게 한도

    // 물건 정보: {무게, 가치}
    vector<int> weight = {1, 3, 4, 5};
    vector<int> value  = {1, 4, 5, 7};

    // dp[i][w] = 물건 0~(i-1)까지 고려, 무게 한도 w에서 최대 가치
    // (N+1) x (W+1) 테이블, 0으로 초기화
    vector<vector<int>> dp(N + 1, vector<int>(W + 1, 0));

    for (int i = 1; i <= N; i++) {
        for (int w = 0; w <= W; w++) {
            // 현재 물건 i-1번 (0-indexed)
            if (weight[i - 1] > w) {
                // 무게 초과: 넣을 수 없음 → 이전 결과 그대로
                dp[i][w] = dp[i - 1][w];
            } else {
                // 넣거나 / 안 넣거나 중 더 큰 값 선택
                dp[i][w] = max(
                    dp[i - 1][w],                              // 안 넣기
                    dp[i - 1][w - weight[i - 1]] + value[i - 1]  // 넣기
                );
            }
        }
    }

    // 결과 출력
    cout << "=== 0/1 배낭 문제 ===" << endl;
    cout << "물건 수: " << N << ", 무게 한도: " << W << endl;
    cout << "최대 가치: " << dp[N][W] << endl;

    // DP 테이블 출력
    cout << "\nDP 테이블 (행=물건수, 열=무게한도):" << endl;
    cout << "    ";
    for (int w = 0; w <= W; w++) cout << setw(3) << w;
    cout << endl;
    for (int i = 0; i <= N; i++) {
        cout << "i=" << i << ":";
        for (int w = 0; w <= W; w++) cout << setw(3) << dp[i][w];
        cout << endl;
    }

    // 어떤 물건을 담았는지 역추적
    cout << "\n선택된 물건: ";
    int w = W;
    for (int i = N; i >= 1; i--) {
        if (dp[i][w] != dp[i - 1][w]) {
            // 이 물건을 넣었음
            cout << "(무게=" << weight[i - 1] << ", 가치=" << value[i - 1] << ") ";
            w -= weight[i - 1];
        }
    }
    cout << endl;

    return 0;
}
```

### 시간/공간 복잡도

| 항목 | 복잡도 | 비고 |
|------|--------|------|
| 시간 | O(N × W) | **의사 다항(pseudo-polynomial)**: W가 입력 *값*이라 비트 수 기준으로는 지수적. W=10^8이면 사실상 불가능 |
| 공간 2D | O(N × W) | 기본 구현 |
| 공간 1D | O(W) | 롤링 배열로 축소 가능 |

> **의사 다항(pseudo-polynomial) 설명**: O(N×W)은 언뜻 다항처럼 보이지만, W를 *비트 수* b로 표현하면 W = 2^b이므로 실제 시간은 입력 크기에 지수적이다. 0/1 배낭은 NP-완전 문제이며, W가 작을 때만 DP가 실용적이다. "W가 10^8이면 불가능"이라는 경고의 정확한 이유가 바로 이것이다.

**1D 최적화**: `dp[w] = max(dp[w], dp[w - weight[i]] + value[i])` 를 **w를 W에서 0으로 역방향** 루프돌리면 O(W) 공간으로 해결 가능.

### 심화 — 1D 롤링 배열 0/1 배낭

```cpp
// g++ -std=c++17 -Wall -o wk3_4b.bin wk3_4b.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int N = 4, W = 7;
    vector<int> weight = {1, 3, 4, 5};
    vector<int> value  = {1, 4, 5, 7};

    // 1D dp: dp[w] = 무게 한도 w에서 얻을 수 있는 최대 가치
    // (2D의 "현재 행"만 유지하는 롤링 배열)
    vector<int> dp(W + 1, 0);

    for (int i = 0; i < N; i++) {
        // ★ 핵심: w를 큰 값(W)에서 작은 값(weight[i])으로 역방향 순회
        // 왜 역방향? w를 작은 값부터 순방향으로 돌리면 같은 물건 i를
        // dp[w - weight[i]]에서 이미 "한 번 넣은 상태"로 또 넣게 된다 (무한배낭).
        // 역방향으로 돌리면 dp[w - weight[i]]는 아직 물건 i를 반영 전 값이다.
        for (int w = W; w >= weight[i]; w--) {
            dp[w] = max(dp[w],                          // 물건 i 안 넣기
                        dp[w - weight[i]] + value[i]);  // 물건 i 넣기
        }
    }

    cout << "1D 롤링 배낭 최대 가치: " << dp[W] << "\n";  // 기대값: 9
    return 0;
}
```

### 자주 하는 실수

- **1D 최적화 시 루프 방향 실수**: 1D 배낭에서 `w`를 **작은 값부터** 반복하면 같은 물건을 여러 번 넣는 "무한 배낭" 문제가 된다. 0/1 배낭은 반드시 **큰 값부터 역방향**으로.
- **인덱스 1-based vs 0-based 혼용**: `weight[i-1]`인지 `weight[i]`인지 헷갈리면 배열 범위 초과 또는 엉뚱한 물건 선택. 상태 정의에서 "물건 i-1번"인지 "물건 i번"인지 명확히 고정할 것.
- **W가 매우 클 때 시간/메모리 초과**: O(N×W)는 의사 다항 시간이므로 W가 10^8이면 불가능. 이 경우 다른 알고리즘(예: 분기한정, 근사 알고리즘) 필요.

### 연습문제

1. **[BOJ 12865] 평범한 배낭** — 0/1 배낭 기본 문제. N≤100, W≤100000.
2. **[BOJ 7579] 앱** — 배낭 문제의 변형. "메모리"를 최대화하고 "비용"을 최소화.

## 6. 2D DP — LCS (Longest Common Subsequence)

> **30초 요약**: 두 문자열에서 **공통으로 등장하는 가장 긴 부분 수열**의 길이를 구한다. 부분 수열은 연속하지 않아도 된다.

### 일상 비유

두 친구가 각자 좋아하는 노래 플레이리스트가 있다. 순서를 바꾸지 않고, 두 리스트에서 **공통으로 들어가는 노래 목록** 중 가장 긴 것을 찾는 것이 LCS다.

### LCS vs LCS (헷갈리지 마!)

| 용어 | 의미 |
|------|------|
| **LCS** (Longest Common **Subsequence**) | 공통 **부분 수열** — 연속 아니어도 됨 |
| **LCS** (Longest Common **Substring**) | 공통 **부분 문자열** — 연속이어야 함 |

이번에는 **Subsequence** 버전이다.

### 시각화 — DP 테이블 채우기

`s1 = "ABCDE"`, `s2 = "ACE"`:

```
dp[i][j] = s1[0..i-1]과 s2[0..j-1]의 LCS 길이

       ""  A  C  E
    ""  0   0  0  0
    A   0   1  1  1
    B   0   1  1  1
    C   0   1  2  2
    D   0   1  2  2
    E   0   1  2  3
              ↑ 답 = 3 (LCS = "ACE")

채우는 규칙:
  s1[i-1] == s2[j-1] → dp[i][j] = dp[i-1][j-1] + 1  (두 문자 일치!)
  s1[i-1] != s2[j-1] → dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

### 점화식

```
dp[i][j] = "s1[0..i-1]과 s2[0..j-1]의 LCS 길이"

if s1[i-1] == s2[j-1]:
    dp[i][j] = dp[i-1][j-1] + 1      // 두 문자 모두 LCS에 포함
else:
    dp[i][j] = max(dp[i-1][j],        // s1에서 한 글자 버리기
                   dp[i][j-1])         // s2에서 한 글자 버리기

초기값:
  dp[0][j] = 0  (s1이 빈 문자열)
  dp[i][0] = 0  (s2가 빈 문자열)

최종 답: dp[len(s1)][len(s2)]
```

### 동작 원리 — 단계별

1. (m+1) × (n+1) 크기 dp 테이블을 0으로 초기화 (m = s1 길이, n = s2 길이).
2. `i = 1 ~ m`, `j = 1 ~ n` 이중 루프.
3. `s1[i-1] == s2[j-1]`이면 왼쪽 위 대각선 + 1. 아니면 위쪽과 왼쪽 중 최댓값.
4. `dp[m][n]`이 LCS 길이.

**왜 대각선 + 1인가?** `s1[i-1]`과 `s2[j-1]`이 같다면, 두 문자 모두 LCS에 포함시킬 수 있다. `dp[i-1][j-1]`은 "두 문자를 아직 보지 않은 상태에서의 LCS"이므로, 거기에 1을 더하면 된다.

### C++ 코드

```cpp
// g++ -std=c++17 -Wall -o wk3_5.bin wk3_5.cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 데모 입력
    string s1 = "AGGTAB";
    string s2 = "GXTXAYB";
    int m = s1.size();
    int n = s2.size();

    // dp[i][j] = s1[0..i-1]과 s2[0..j-1]의 LCS 길이
    // (m+1) x (n+1) 크기, 0으로 초기화 (첫 행/열이 베이스 케이스)
    vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));

    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (s1[i - 1] == s2[j - 1]) {
                // 두 문자가 같음: 대각선 + 1
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                // 두 문자가 다름: 위쪽 또는 왼쪽 중 큰 값
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }

    cout << "=== LCS (Longest Common Subsequence) ===" << endl;
    cout << "s1 = \"" << s1 << "\"" << endl;
    cout << "s2 = \"" << s2 << "\"" << endl;
    cout << "LCS 길이: " << dp[m][n] << endl;

    // DP 테이블 출력
    cout << "\nDP 테이블:" << endl;
    cout << "      ";
    for (char c : s2) cout << setw(3) << c;
    cout << endl;
    for (int i = 0; i <= m; i++) {
        if (i == 0) cout << "   ";
        else cout << " " << s1[i - 1] << " ";
        for (int j = 0; j <= n; j++) cout << setw(3) << dp[i][j];
        cout << endl;
    }

    // LCS 실제 문자열 역추적
    string lcs = "";
    int i = m, j = n;
    while (i > 0 && j > 0) {
        if (s1[i - 1] == s2[j - 1]) {
            lcs += s1[i - 1];  // 공통 문자 → LCS에 포함
            i--; j--;
        } else if (dp[i - 1][j] > dp[i][j - 1]) {
            i--;  // 위쪽에서 왔음
        } else {
            j--;  // 왼쪽에서 왔음
        }
    }
    reverse(lcs.begin(), lcs.end());  // 역추적이라 뒤집어야 함
    cout << "\nLCS 문자열: \"" << lcs << "\"" << endl;

    return 0;
}
```

### 시간/공간 복잡도

| 항목 | 복잡도 |
|------|--------|
| 시간 | O(m × n) |
| 공간 | O(m × n) → 1D 롤링으로 O(min(m,n)) 가능 |

### 자주 하는 실수

- **LCS 역추적 방향 혼동**: 역추적 시 `dp[i-1][j] >= dp[i][j-1]`처럼 등호 처리를 어떻게 하느냐에 따라 LCS 경로가 달라진다. 길이는 동일하지만 경로가 여러 개일 수 있다.
- **인덱스 1-based 혼용**: `dp[i][j]`가 `s1[i-1]`과 `s2[j-1]`을 보는 것인지 `s1[i]`와 `s2[j]`를 보는 것인지 일관성 유지 필수.
- **LCS vs Edit Distance 혼동**: Edit Distance(Levenshtein)도 2D DP이지만 점화식이 다르다. "같으면 그대로 + 1, 다르면 max" vs "같으면 그대로, 다르면 1+min(3가지)" — 문제가 다르다.

## 이번 주 핵심 정리

| 문제 | DP 상태 | 점화식 | 시간 복잡도 |
|------|---------|--------|------------|
| **피보나치** | `dp[n]` = n번째 피보나치 수 | `dp[n] = dp[n-1] + dp[n-2]` | O(n) |
| **계단 오르기** | `dp[i]` = i번째 계단까지 오는 방법 수 | `dp[i] = dp[i-1] + dp[i-2]` | O(n) |
| **LIS** | `dp[i]` = arr[i] 마지막으로 하는 LIS 길이 | `dp[i] = max(dp[j]+1)` (j<i, arr[j]<arr[i]) | O(n²) |
| **0/1 배낭** | `dp[i][w]` = 물건 i개 고려, 무게 w에서 최대 가치 | `max(안 넣기, 넣기)` | O(N×W) |
| **LCS** | `dp[i][j]` = s1[0..i-1]과 s2[0..j-1]의 LCS 길이 | 같으면 대각선+1, 다르면 max(위, 왼) | O(m×n) |

### DP 점화식 도출 4단계 (다시 한번!)

```
1. 상태 정의   → dp[i]가 정확히 무엇인지 한 문장으로
2. 답의 위치   → dp[n]? max(dp)? dp[n][W]?
3. 점화식      → 이전 상태들과의 관계식
4. 초기값/순서 → 베이스 케이스 + 작은 것부터 채우기
```

### 마지막으로

DP는 유형이 수십 가지이고, 각 유형마다 상태 정의가 다르다. 처음엔 모든 문제가 새롭게 느껴지지만, **같은 유형을 5번 이상 직접 점화식 세워서 풀어보면** 어느 순간 패턴이 보이기 시작한다. "점화식이 안 세워진다" → 정답 풀이를 보되, **왜 그 상태를 정의했는지**를 이해하는 데 집중하자. 코드는 그 다음이다.

> "DP를 처음 배우면 70%는 '이해했다'고 착각한다. 나머지 30%가 진짜다."
