# 4주차 — 그리디 (Greedy)

> **이미지 참조**: `../images/prompts/week4_greedy_intro.txt` 프롬프트로 생성한 이미지를 `../images/week4_greedy_intro.png`에 저장하면 여기에 자동으로 표시됩니다.
> ![그리디 인트로](../images/week4_greedy_intro.png)

---

알고리즘을 배우다 보면 "이 문제, 그냥 매 순간 제일 좋은 걸 고르면 되지 않나?"라는 생각이 들 때가 있다. 그 직관이 바로 **그리디(Greedy, 탐욕법)** 다. 그리디는 "지금 이 순간 가장 좋아 보이는 선택"을 반복해서 전체 최적해를 구하는 전략이다. 복잡한 경우의 수를 모두 따지지 않아도 되니 빠르고 간결하다.

그러나 주의해야 한다. 그리디가 통하려면 **"지금 최선 = 전체 최선"이 성립하는 문제 구조** 가 갖춰져 있어야 한다. 이 조건이 없으면 그리디는 틀린 답을 내뱉는다. 이 주차에서는 "왜 그리디가 옳은지"를 직관적으로 이해하는 **교환 논법(Exchange Argument)** 과 함께, 실전에서 자주 나오는 세 가지 대표 문제(동전 거스름돈, 회의실 배정, 분수 배낭)를 차례로 살펴본다.

이 세 문제는 알고리즘 대회의 단골 손님일 뿐만 아니라, 그리디 풀이가 **왜** 성립하는지를 가장 명확하게 설명해 주는 예제들이다. 각 문제에서 "어떤 기준으로 정렬/선택하는가"와 "그 기준을 바꾸면 손해가 생긴다"는 교환 논법을 체득하면, 처음 보는 그리디 문제도 스스로 풀이를 설계할 수 있게 된다.

## 1. 그리디란 무엇인가

### 1-1. "지금 이 순간 최선의 선택"

그리디는 매 단계마다 **현재 상태에서 가장 이득인 선택** 을 하고, 그 선택을 번복하지 않는다. 전체 경우의 수를 탐색하지 않으므로 대부분 O(N log N) 이하의 빠른 시간 안에 답을 낸다.

```
전체 탐색 (Brute Force): 모든 경우를 다 봄 → 느리지만 항상 정확
다이나믹 프로그래밍:  부분 문제 결과를 저장·재활용 → 빠르고 정확
그리디:              매 순간 최선만 선택 → 가장 빠르지만 조건 필요
```

### 1-2. 그리디가 항상 옳지 않은 반례 — 동전 1, 3, 4원으로 6원 만들기

동전이 **1원, 3원, 4원** 이 있고 **6원** 을 만든다고 하자.

- **그리디 전략** (가장 큰 동전부터): 4 → 남은 2원 → 1+1  
  총 **3개** (4+1+1)
- **최적해**: 3+3  
  총 **2개** ← 그리디보다 적다!

큰 동전을 먼저 택하는 그리디가 이 경우엔 **틀린다**. 왜냐하면 4원 동전을 선택하는 순간 "3+3" 경로를 닫아버리기 때문이다. 이 문제는 DP(동적 프로그래밍)로 풀어야 한다.

```
동전: 1원 □  3원 □  4원 □
목표: 6원

그리디:  [4] → [4,1] → [4,1,1]  = 3개  (틀림!)
최적:   [3] → [3,3]              = 2개
```

### 1-3. 그리디가 옳을 때 — 교환 논법 (Exchange Argument)

그리디가 내놓은 해 **G** 와 임의의 다른 해 **O** 가 있다고 하자. "G에서 한 선택을 O의 선택으로 바꾸면 손해가 생기거나 같다"는 것을 보이면, G가 최적이거나 최적과 동등함을 증명할 수 있다. 이것이 **교환 논법** 의 핵심 구조다.

- "현재 선택을 다른 선택으로 교환(swap)했더니 결과가 나빠지거나 같다" → 그리디의 선택이 옳다.
- 각 알고리즘 섹션에서 이 논법을 직관적으로 적용해 볼 것이다.

### 1-4. 그리디 vs DP 비교표

| 기준 | 그리디 | 다이나믹 프로그래밍 |
|---|---|---|
| 선택 방식 | 매 순간 최선 1가지만 선택 | 모든 부분 문제 결과를 비교 |
| 선택 번복 | 절대 안 함 | 메모이제이션으로 최적 경로 역추적 가능 |
| 적용 조건 | 탐욕 선택 성질 + 최적 부분 구조 | 최적 부분 구조 (탐욕 선택 성질 불필요) |
| 시간 복잡도 | 보통 O(N) ~ O(N log N) | 보통 O(N²) ~ O(N·W) 이상 |
| 공간 복잡도 | O(1) ~ O(N) | O(N) ~ O(N·W) |
| 대표 문제 | 동전(표준), 회의실 배정, MST | 동전(임의), 배낭 0/1, LCS |
| 실수 위험 | "정말 그리디가 성립하나?" 증명 빠뜨리기 | 점화식 방향 틀리기, 초기값 오류 |

**언제 그리디를 먼저 생각하나?**

1. 정렬 후 순서대로 선택하면 최적이 나올 것 같을 때
2. 선택을 번복해도 이득이 없을 때
3. 문제가 "최소 개수", "최대 개수/이익"을 물을 때

## 2. 동전 거스름돈 (Coin Change — Canonical)

> **30초 요약**: 한국 동전(500/100/50/10/5/1)에서는 큰 동전부터 최대한 쓰면 항상 최소 개수로 거슬러 줄 수 있다.

> **이미지 참조**: `../images/prompts/week4_coin_change.txt`
> ![동전 거스름돈](../images/week4_coin_change.png)

### 일상 비유

편의점 알바를 하다가 손님에게 730원을 거슬러 줘야 한다. 지갑을 열어 보니 동전이 잔뜩 있다. 자연스럽게 500원짜리 1개, 100원짜리 2개, 10원짜리 3개를 내놓는다. 이게 그리디다. "지금 쓸 수 있는 가장 큰 동전"을 반복해서 고른다.

### 시각화

```
목표: 730원 거슬러 주기
동전 종류: 500 100 50 10 5 1

Step 1: 500 ≤ 730  → 500원 1개 사용   남은 금액: 230원
Step 2: 500 > 230  → 500원 패스
        100 ≤ 230  → 100원 1개 사용   남은 금액: 130원
Step 3: 100 ≤ 130  → 100원 1개 사용   남은 금액:  30원
Step 4: 100 > 30   → 100원 패스
         50 > 30   →  50원 패스
         10 ≤ 30   →  10원 1개 사용   남은 금액:  20원
Step 5:  10 ≤ 20   →  10원 1개 사용   남은 금액:  10원
Step 6:  10 ≤ 10   →  10원 1개 사용   남은 금액:   0원

결과: 500×1 + 100×2 + 10×3 = 6개 (최솟값)
```

### 그리디 전략

동전을 **내림차순으로 정렬**한 뒤, 각 동전에 대해 "현재 금액으로 몇 개 쓸 수 있나?"를 계산하고 그만큼 사용한 뒤 다음 동전으로 넘어간다. 큰 동전 1개 = 작은 동전 여러 개이므로, 항상 큰 것부터 쓰는 게 개수를 줄이는 최선이다.

### 왜 그리디가 옳은가? (직관)

한국 동전 500, 100, 50, 10, 5, 1은 **각 동전이 바로 아래 동전의 정수배** 관계다(500 = 5×100, 100 = 2×50, 50 = 5×10, 10 = 2×5, 5 = 5×1). 이렇게 깔끔한 정수배 구조면 그리디가 모든 금액에서 최적이다.

> **용어 주의**: 일반적으로 "그리디가 *모든* 금액에서 최적인 동전 시스템"을 **정준(canonical) 동전 시스템**이라 부른다. "정수배 구조"는 정준의 *충분조건*일 뿐 정의가 아니다. 예를 들어 미국 동전 `{1, 5, 10, 25}`는 정수배가 아닌데도 정준이고, 반대로 `{1, 7, 10}`은 합으로 표현은 가능하지만 정준이 아니다(목표 14: 그리디=10+1+1+1+1=5개, 최적=7+7=2개).

교환 논법으로 확인: 한국 동전에서 최적해 O가 500원 동전을 더 적게 쓰고 100원 동전을 더 많이 쓴다고 하자. 500원짜리 1개를 100원짜리 5개로 바꾸면 개수가 +4 늘어난다. 따라서 큰 동전을 줄이는 것은 항상 손해다. 즉, 그리디가 최적이다.

단, 1-2절의 반례(1,3,4원)처럼 정수배/정준 구조가 깨지면 그리디는 틀린다. 그런 경우는 DP로 풀어야 한다.

### 동작 원리 — 단계별

1. 동전 배열을 **내림차순** 으로 정렬한다.
2. 가장 큰 동전부터 순서대로:
   - `count = 남은 금액 / 동전 가치` (정수 나눗셈)
   - 총 동전 수에 `count`를 더한다.
   - 남은 금액에서 `count × 동전 가치`를 뺀다.
3. 남은 금액이 0이 될 때까지 반복한다.

### C++ 코드

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 한국 동전 종류 (내림차순으로 미리 정렬되어 있음)
    vector<int> coins = {500, 100, 50, 10, 5, 1};

    int amount = 730; // 거슬러 줘야 할 금액 (데모)
    int totalCount = 0;

    cout << "목표 금액: " << amount << "원\n";
    cout << "---\n";

    for (int coin : coins) {
        if (amount <= 0) break;          // 이미 다 거슬렀으면 종료

        int count = amount / coin;       // 이 동전으로 몇 개 쓸 수 있나?
        if (count > 0) {
            cout << coin << "원짜리 " << count << "개 사용, ";
        }
        totalCount += count;             // 총 개수에 누적
        amount -= count * coin;          // 남은 금액 감소

        if (count > 0) {
            cout << "남은 금액: " << amount << "원\n";
        }
    }

    cout << "---\n";
    if (amount > 0) {
        // 1원 동전이 없거나 정수배 구조가 깨진 동전 셋이라면 표현 불가능할 수 있다
        cout << "이 동전 조합으로는 정확히 표현할 수 없습니다. 남은 금액: " << amount << "원\n";
    } else {
        cout << "필요한 최소 동전 개수: " << totalCount << "개\n";
    }
    return 0;
}
```

**예상 출력**:
```
목표 금액: 730원
---
500원짜리 1개 사용, 남은 금액: 230원
100원짜리 2개 사용, 남은 금액: 30원
10원짜리 3개 사용, 남은 금액: 0원
---
필요한 최소 동전 개수: 6개
```

### 시간/공간 복잡도

| 항목 | 복잡도 | 이유 |
|---|---|---|
| 시간 | O(K) | K = 동전 종류 수 (한국 동전은 K=6으로 상수) |
| 공간 | O(K) | 동전 배열 저장 |

### 자주 하는 실수

1. **동전 배열을 정렬하지 않는다**: 입력으로 동전이 임의 순서로 주어지면 반드시 내림차순 정렬 후 처리해야 한다. 정렬 없이 순서대로 처리하면 틀린 답이 나온다.
2. **그리디 적용 조건을 확인하지 않는다**: 문제에서 동전 종류가 임의로 주어지면(예: 1, 3, 4원) 그리디가 틀릴 수 있다. "동전이 배수 구조냐?"를 먼저 따져야 한다. 일반적인 최소 동전 개수 문제는 DP로 풀어야 안전하다.
3. **정수 나눗셈 vs 실수 나눗셈 혼동**: `amount / coin`은 C++에서 정수 나눗셈이므로 올바르게 동작한다. `(double)amount / coin`으로 쓰면 개수 계산이 틀어진다.

## 3. 회의실 배정 (Activity / Meeting Selection)

> **30초 요약**: 회의 종료 시간이 빠른 순으로 정렬한 뒤, 이전 회의가 끝난 후 시작하는 회의를 탐욕적으로 고르면 한 회의실에서 최대 개수의 회의를 배정할 수 있다.

> **이미지 참조**: `../images/prompts/week4_activity_selection.txt`
> ![회의실 배정](../images/week4_activity_selection.png)

### 일상 비유

하루 동안 회의실 1칸을 가능한 한 많은 회의에 빌려주고 싶다. 회의 신청서 10장이 쌓여 있다. 어떤 회의부터 배정해야 할까? **"가장 일찍 끝나는 회의를 먼저 넣는다"** — 방을 빨리 비울수록 다음 회의를 더 많이 받을 수 있기 때문이다.

### 시각화

```
회의 목록 (시작, 끝):
  A: [1, 4)
  B: [3, 5)
  C: [0, 6)
  D: [5, 7)
  E: [3, 8)
  F: [5, 9)
  G: [6, 10)
  H: [8, 11)
  I: [8, 12)
  J: [2, 13)

끝 시간 기준 정렬:
  A[1,4) B[3,5) C[0,6) D[5,7) E[3,8) F[5,9) G[6,10) H[8,11) I[8,12) J[2,13)

타임라인:
0    2    4    6    8    10   12
|    |    |    |    |    |    |
[A=========)                        ← 선택 (끝=4)
     [B========)                    ← 끝=4이 아직 지나지 않아서 건너뜀 (시작3<4)
     [C=============)               ← 건너뜀 (시작0<4)
               [D======)            ← 선택 (시작5≥4, 끝=7)
               [E===========)       ← 건너뜀 (시작3<7)
               [F============)      ← 건너뜀 (시작5<7)
                    [G=========)    ← 건너뜀 (시작6<7)
                         [H======)  ← 선택 (시작8≥7, 끝=11)
                         [I=======) ← 건너뜀 (시작8<11)
[J=========================)        ← 건너뜀 (시작2<11)

선택된 회의: A, D, H  → 최대 3개
```

### 그리디 전략

회의를 **종료 시간(end time) 기준으로 오름차순 정렬** 한다. 이후 순서대로 회의를 살피면서, 현재 회의의 **시작 시간 ≥ 마지막으로 선택된 회의의 종료 시간** 이면 선택한다.

종료 시간이 빠른 회의를 먼저 고르면 다음 회의를 받을 수 있는 여유(남은 시간)가 최대한 많이 남기 때문에 전체 선택 개수가 최대가 된다.

### 왜 그리디가 옳은가? (직관)

교환 논법 (3단계):

1. **`end(a) ≤ end(b)`인 이유**: 처음에는 G와 O 모두 *모든 회의*가 후보다. G는 정의상 `end(a)`가 가장 작은 회의를 고르므로, O가 어떤 회의 b를 골랐든 `end(a) ≤ end(b)` 가 자동 성립한다.

2. **교환 안전성**: O의 첫 선택 b를 a로 바꿔 새 해 O'을 만든다. b 다음에 O가 고를 수 있던 회의들은 모두 `start ≥ end(b) ≥ end(a)` 조건을 만족하므로, **a 다음에도 그대로 선택 가능**하다. 따라서 |O'| = |O|.

3. **귀납적 마무리**: 이제 "a 이후에 선택 가능한 회의들"이라는 부분 문제가 남는다. 그 부분 문제에서도 G는 가장 빨리 끝나는 회의를 고르고, O'은 임의의 다른 첫 회의를 고른다 — 같은 논리를 반복 적용하면 |G| ≥ |O'| = |O| 이 성립한다. 즉 G는 최적과 같거나 더 좋다 → G는 최적이다.

**시작 시간 기준으로 정렬하면 왜 틀릴까?**

```
회의: [1,10), [2,3), [4,5)
시작 시간 정렬: [1,10)이 가장 먼저 → 선택 → 나머지 2개 모두 건너뜀 → 1개 선택
종료 시간 정렬: [2,3) 선택, [4,5) 선택 → 2개 선택 ← 최적
```

### 동작 원리 — 단계별

1. 회의 배열을 **종료 시간 오름차순** 으로 정렬한다. (종료 시간이 같으면 시작 시간 오름차순)
2. `lastEnd = -1` (초기값: 어떤 시작 시간보다 작은 값), `count = 0` 으로 초기화한다.
3. 정렬된 순서대로 각 회의 `[s, e)` 를 검사:
   - `s >= lastEnd` 이면 이 회의를 선택한다: `count++`, `lastEnd = e`
   - 아니면 건너뛴다.
4. `count` 를 출력한다.

### C++ 코드

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 회의 목록: {시작 시간, 끝 시간} — 끝 시간은 해당 시각에 방을 비운다고 가정
    vector<pair<int,int>> meetings = {
        {1, 4}, {3, 5}, {0, 6}, {5, 7}, {3, 8},
        {5, 9}, {6, 10}, {8, 11}, {8, 12}, {2, 13}
    };

    // 핵심: 끝 시간 오름차순 정렬, 끝 시간 같으면 시작 시간 오름차순
    sort(meetings.begin(), meetings.end(), [](const pair<int,int>& a, const pair<int,int>& b) {
        if (a.second != b.second) return a.second < b.second; // 끝 시간 먼저 비교
        return a.first < b.first;                             // 끝 시간 같으면 시작 시간
    });

    int lastEnd = -1; // 마지막으로 선택된 회의의 종료 시간
    int count = 0;    // 선택된 회의 수

    cout << "선택된 회의 목록:\n";
    for (auto& [s, e] : meetings) {           // C++17 구조적 바인딩
        if (s >= lastEnd) {                   // 이전 회의가 끝난 후에 시작하면 선택
            cout << "  [" << s << ", " << e << ")\n";
            lastEnd = e;                      // 종료 시간 갱신
            count++;
        }
    }

    cout << "최대 회의 개수: " << count << "\n";
    return 0;
}
```

**예상 출력**:
```
선택된 회의 목록:
  [1, 4)
  [5, 7)
  [8, 11)
최대 회의 개수: 3
```

### 시간/공간 복잡도

| 항목 | 복잡도 | 이유 |
|---|---|---|
| 시간 | O(N log N) | 정렬이 지배적; 이후 스캔은 O(N) |
| 공간 | O(N) | 회의 배열 저장 |

### 자주 하는 실수

1. **시작 시간 기준으로 정렬한다**: 직관적으로 "일찍 시작하는 것부터"라고 생각하기 쉽다. 하지만 앞의 반례처럼 시작이 빠른 회의가 오래 걸리면 뒤의 짧은 회의들을 모두 막아버린다. 반드시 **종료 시간** 기준으로 정렬해야 한다.
2. **`lastEnd` 초기값을 0으로 설정한다**: 시작 시간이 0인 회의가 있을 때 `0 >= 0` 이므로 선택되긴 하지만, 시작 시간이 음수인 케이스(문제에 따라)나 비교 조건을 `>` 로 쓴 경우 놓칠 수 있다. `lastEnd = -1` 또는 `INT_MIN` 으로 초기화하는 것이 안전하다.
3. **종료 시간이 같을 때 정렬 기준을 빠뜨린다**: `sort`의 비교 함수에서 종료 시간만 비교하면 동일 종료 시간을 가진 회의 간 순서가 불안정하다. C++ `sort`는 불안정 정렬이므로 동점 기준을 명시해야 한다.

## 4. 분수 배낭 (Fractional Knapsack)

> **30초 요약**: 물건을 **잘라서** 담을 수 있는 배낭 문제. 가치/무게 비율이 높은 순으로 정렬해 꽉 찰 때까지 담으면 최대 가치를 얻는다.

> **이미지 참조**: `../images/prompts/week4_fractional_knapsack.txt`
> ![분수 배낭](../images/week4_fractional_knapsack.png)

### 일상 비유

금 가루, 은 가루, 구리 가루가 각각 자루에 담겨 있다. 들고 다닐 수 있는 가방 무게 한도가 있을 때, 가방을 최대한 비싸게 채우려면 어떻게 해야 할까? 당연히 **그램당 가격이 높은 것부터** 담으면 된다. 자루를 조금 잘라 담아도 되니, 딱 한도에 맞게 채울 수 있다.

### 시각화

```
배낭 용량: 50kg
물건 목록:
  물건  무게(kg)  가치(원)  단위 가치(원/kg)
  ---   --------  --------  ----------------
   A      10       60           6.0
   B      20       100          5.0
   C      30       120          4.0

단위 가치 내림차순 정렬: A(6.0) > B(5.0) > C(4.0)

Step 1: A 전체 담기 (10kg, +60원)  남은 용량: 40kg  누적 가치: 60원
Step 2: B 전체 담기 (20kg, +100원) 남은 용량: 20kg  누적 가치: 160원
Step 3: C는 30kg인데 남은 용량이 20kg
        → C의 20/30 = 2/3 만큼만 잘라서 담기
        → 가치 += 120 × (20/30) = 80원
        남은 용량: 0kg   누적 가치: 240원

최적 가치: 240원
```

```
배낭 [=== A(10kg) === B(20kg) === C의 2/3(20kg) ===]
      ←──────────────── 50kg ─────────────────────→
```

### 그리디 전략

물건을 **단위 무게당 가치(가치 ÷ 무게) 기준으로 내림차순 정렬** 한다. 용량이 남아 있는 동안 앞에서부터 순서대로 담는다. 물건이 남은 용량보다 무거우면 **그 비율만큼만 잘라** 담고 종료한다.

### 왜 그리디가 옳은가? (직관)

교환 논법: 최적해 O에서 단위 가치가 낮은 물건 X의 일부 대신 단위 가치가 높은 물건 Y의 일부로 교환하면, 같은 무게에서 가치가 증가하거나 같다. 따라서 단위 가치가 높은 것을 먼저 담는 그리디는 최적이다.

**0/1 배낭(물건을 자를 수 없는 경우)과의 차이**: 0/1 배낭에서는 물건을 통째로 넣거나 포기해야 한다. 이 경우 단위 가치 기준 그리디는 틀릴 수 있다.

```
예시: 용량 5kg, 물건 A(4kg, 5원), B(3kg, 4원), C(3kg, 4원)
분수 배낭 그리디:
  단위가치: A=1.25, B≈1.333, C≈1.333  (B, C 동률 → A보다 높음)
  B 전체(3kg, +4원) → 남은 2kg → C의 2/3만큼(+8/3 ≈ 2.667원)
  → 합계 ≈ 6.667원
  (B를 다 채우고 남은 2kg는 단위가치가 더 높은 C 일부를 자르는 게 최선)

0/1 배낭 최적:
  B+C = 6kg > 5kg → 불가
  A+B = 7kg > 5kg → 불가
  A만 = 5원
  B만 = 4원
  C만 = 4원
  → 최대 5원 (A 선택)

  분수 배낭에서는 잘라서 ≈6.667원을 얻었지만,
  0/1 배낭에서는 통째로만 넣어야 하므로 5원이 최대다.
```

따라서 0/1 배낭은 반드시 DP로 풀어야 한다.

### 동작 원리 — 단계별

1. 각 물건의 `단위 가치 = 가치 / 무게`를 계산한다.
2. **단위 가치 내림차순** 으로 물건을 정렬한다.
3. `remainCapacity = W`, `totalValue = 0.0` 으로 초기화한다.
4. 정렬된 순서대로 각 물건 `(w, v)` 를 처리:
   - `w ≤ remainCapacity` 이면 통째로 담는다: `totalValue += v`, `remainCapacity -= w`
   - `w > remainCapacity` 이면 비율만큼 담는다: `totalValue += v × (remainCapacity / w)`, 종료
5. `totalValue` 를 출력한다.

### C++ 코드

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 배낭 최대 용량 (kg)
    double capacity = 50.0;

    // {무게, 가치} 쌍으로 물건 정의 (데모)
    vector<pair<double,double>> items = {
        {10, 60},   // 물건 A: 10kg, 60원
        {20, 100},  // 물건 B: 20kg, 100원
        {30, 120},  // 물건 C: 30kg, 120원
    };

    // 단위 가치(가치/무게) 내림차순 정렬
    sort(items.begin(), items.end(), [](const pair<double,double>& a, const pair<double,double>& b) {
        return (a.second / a.first) > (b.second / b.first); // 단위 가치 높은 것 먼저
    });

    double totalValue = 0.0;   // 누적 가치
    double remaining = capacity; // 남은 배낭 용량

    cout << fixed << setprecision(2); // 소수점 2자리 출력
    cout << "배낭 용량: " << capacity << "kg\n";
    cout << "---\n";

    for (auto& [w, v] : items) { // C++17 구조적 바인딩
        if (remaining <= 0.0) break; // 배낭이 꽉 찼으면 종료

        if (w <= remaining) {
            // 물건 전체를 담을 수 있다
            totalValue += v;
            remaining -= w;
            cout << "전체 담기: " << w << "kg, +" << v << "원 (남은 용량: " << remaining << "kg)\n";
        } else {
            // 일부만 잘라서 담는다
            double fraction = remaining / w;        // 담는 비율 (0~1)
            double partialValue = v * fraction;     // 비율에 해당하는 가치
            totalValue += partialValue;
            cout << "일부 담기: " << remaining << "kg (" << (fraction * 100) << "%), +"
                 << partialValue << "원\n";
            remaining = 0.0;
        }
    }

    cout << "---\n";
    cout << "최대 가치: " << totalValue << "원\n";
    return 0;
}
```

**예상 출력**:
```
배낭 용량: 50.00kg
---
전체 담기: 10kg, +60원 (남은 용량: 40.00kg)
전체 담기: 20kg, +100원 (남은 용량: 20.00kg)
일부 담기: 20.00kg (66.67%), +80.00원
---
최대 가치: 240.00원
```

### 시간/공간 복잡도

| 항목 | 복잡도 | 이유 |
|---|---|---|
| 시간 | O(N log N) | 정렬이 지배적; 이후 스캔은 O(N) |
| 공간 | O(N) | 물건 배열 저장 |

### 자주 하는 실수

1. **가치 기준으로 정렬한다 (단위 가치가 아닌 총 가치)**: 무게가 무거운 비싼 물건을 먼저 담으면 배낭이 빨리 차서 가성비 좋은 물건을 못 담는다. 반드시 `가치 / 무게` 비율로 정렬해야 한다.
2. **0/1 배낭인데 분수 배낭 알고리즘을 적용한다**: 문제에서 "물건을 잘라서 담을 수 없다"고 하면 DP를 사용해야 한다. 분수 배낭 그리디는 자르는 것이 허용될 때만 옳다.
3. **정수 나눗셈으로 단위 가치를 계산한다**: C++에서 `int v / int w` 는 정수 나눗셈이므로 비율 정보가 손실된다. `double` 또는 `(double)v / w` 형태로 계산해야 한다.

## 이번 주 핵심 정리

| 알고리즘 | 정렬 기준 | 핵심 조건 | 시간 복잡도 |
|---|---|---|---|
| 동전 거스름돈 | 동전 내림차순 | 동전이 정준(배수 구조) | O(K) |
| 회의실 배정 | 종료 시간 오름차순 | 겹치지 않는 최대 선택 | O(N log N) |
| 분수 배낭 | 단위 가치 내림차순 | 물건을 자를 수 있음 | O(N log N) |

### 그리디 문제 풀이 체크리스트

1. **탐욕 선택 성질이 있나?** — "지금 최선 = 전체 최선"이 성립하는지 교환 논법으로 확인.
2. **반례를 먼저 찾아본다** — 작은 예제로 그리디가 틀리는 경우가 있는지 확인. 반례가 나오면 DP나 다른 접근.
3. **정렬 기준을 명확히 한다** — 어떤 속성 기준으로 정렬하면 탐욕 선택이 최적인지 결정.
4. **경계 조건을 처리한다** — 배낭이 꽉 참, 회의가 0개, 동전이 1원만 있는 경우 등.
