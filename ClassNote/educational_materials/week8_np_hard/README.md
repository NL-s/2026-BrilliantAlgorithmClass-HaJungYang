# 8주차 — General NP-Hard

안녕! 이번 주는 알고리즘 세계에서 가장 "악명 높은" 주제, **NP-Hard** 문제들을 다룬다. 처음 들으면 어렵게 느껴지겠지만, 걱정 말자. 오늘 목표는 "NP-Hard 문제를 완벽히 푸는 것"이 아니라 **"어, 이런 문제 구나"라는 감을 잡는 것**이다. 코딩 테스트에서 NP-Hard 문제가 그대로 나오는 경우는 드물고, 대신 N이 작을 때 쓸 수 있는 전략들을 익히는 게 핵심이다.

컴퓨터 과학자들은 수십 년간 "이 문제를 빠르게 풀 수 있는가?"를 연구해 왔는데, 아직도 풀리지 않은 질문이 있다. 바로 **P vs NP** 문제다. 밀레니엄 7대 수학 문제 중 하나로, 풀면 100만 달러 상금이 걸려 있다. 그만큼 어려운 질문이라는 뜻이다.

이번 주는 개념을 이해하고, 유명한 문제들을 훑어보고, 실전에서 쓸 수 있는 **4가지 전략**을 익힌다. 특히 비트마스크 DP를 이용한 TSP(외판원 문제) 구현은 코딩 테스트에 자주 나오니 집중해서 보자.

## 1. P / NP / NP-Hard / NP-Complete — 감으로 이해하기

> **30초 요약**: "푸는 건 어렵지만, 누군가 답을 줬을 때 맞는지 확인하는 건 쉬운 문제"들의 집합이 NP다. NP-Hard는 그보다 더 어렵거나 같은 문제들이고, NP-Complete는 NP이면서 NP-Hard인 문제들이다.

### 일상 비유

> 퍼즐 맞추기를 생각해보자.
>
> - **푸는 것**: 수천 조각짜리 퍼즐을 처음부터 완성하려면 엄청난 시간이 걸린다.
> - **검증하는 것**: 누군가 완성된 퍼즐을 가져오면 "맞게 맞춰졌나요?"는 쓱 보면 금방 알 수 있다.
>
> NP 문제가 딱 이런 성질을 가진다. **정답을 찾는 건 어렵지만, 주어진 답이 맞는지 확인하는 건 빠르다.**

### 시각화

```
┌─────────────────────────────────────────┐
│              모든 문제                   │
│  ┌───────────────────────────────────┐  │
│  │           NP-Hard                 │  │
│  │  ┌─────────────────────────────┐  │  │
│  │  │       NP-Complete           │  │  │
│  │  │  ┌───────────────────────┐  │  │  │
│  │  │  │          NP           │  │  │  │
│  │  │  │  ┌─────────────────┐  │  │  │  │
│  │  │  │  │        P        │  │  │  │  │
│  │  │  │  │  (빠르게 풀림)  │  │  │  │  │
│  │  │  │  └─────────────────┘  │  │  │  │
│  │  │  └───────────────────────┘  │  │  │
│  │  └─────────────────────────────┘  │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

### 개념 정리

| 용어 | 뜻 (직관적으로) | 예시 |
|------|----------------|------|
| **P** | 다항 시간 안에 풀 수 있는 문제 | 정렬, 최단 경로 (다익스트라) |
| **NP** | 답을 주면 다항 시간 안에 검증 가능한 문제 | TSP (결정 버전: "비용 ≤ k 투어 존재?"), SAT, Subset Sum |
| **NP-Hard** | NP의 모든 문제만큼 어렵거나 그 이상인 문제 | TSP (최적화 버전: "최솟값을 구하라"), Halting Problem |

> **결정 버전 vs 최적화 버전**: 같은 TSP라도 "비용 ≤ k 투어가 *존재하는가*"는 결정 문제로 NP-Complete이고, "최소 비용 *값*을 구하라"는 최적화 문제로 NP-Hard지만 NP에 속하지는 않는다. 표에서 TSP가 두 박스에 모두 등장하는 이유다. 학생은 NP-Complete = "결정 버전이 NP에도 들어가고 NP-Hard에도 들어가는 문제"로 기억해 두면 충분하다.
| **NP-Complete** | NP이면서 NP-Hard인 문제 | SAT, Subset Sum |

> **P = NP인가?** 아직 아무도 모른다. 만약 P = NP라면, 답을 검증할 수 있는 모든 문제는 빠르게 풀 수도 있다는 뜻이다. 대부분의 수학자들은 P ≠ NP라고 믿지만, 증명되지 않았다.

### 왜 중요한가?

NP-Complete 문제 하나를 다항 시간에 풀면 **모든 NP 문제가 자동으로 다항 시간에 풀린다**. 그래서 NP-Complete 문제를 "가장 어려운 NP 문제"라고 부른다. 암호화, 스케줄링, 물류 최적화 등 실생활의 중요한 문제들이 NP-Hard에 속한다.

## 2. 유명한 NP 문제들

> **30초 요약**: TSP, SAT, Subset Sum은 NP-Complete의 대표 주자들이다. 각각 외판원, 논리식 만족, 부분합 문제로, 실생활과 밀접하게 연결된다.

### 2-1. TSP (Travelling Salesman Problem, 외판원 문제)

- **문제**: N개 도시를 모두 방문하고 출발지로 돌아오는 **최소 비용 경로**를 찾아라.
- **왜 어렵나**: 도시가 20개만 돼도 경우의 수가 19! ≈ 1.2 × 10¹⁷ 가지다.
- **실생활**: 택배 배달 경로, 반도체 회로 설계, 유전자 분석 등.
- **검증은 쉬운가?**: 누군가 경로를 주면 전체 비용 계산은 O(N)으로 즉시 가능하다.

```
도시 예시 (4개):
   0
  /|\
10/ |15 \20
 /  |    \
1   |     3
 \  |    /
35\ |25 /30
   \|  /
    2
```

### 2-2. SAT (Boolean Satisfiability Problem)

- **문제**: AND, OR, NOT으로 구성된 논리식을 참(TRUE)으로 만드는 변수 값의 조합이 존재하는가?
- **예시**: `(A OR B) AND (NOT A OR C) AND (NOT B OR NOT C)` → A=true, B=false, C=true 로 참 가능.
- **왜 중요한가**: 1971년 Cook이 SAT가 NP-Complete임을 처음 증명했다 (Cook의 정리). 이후 수천 개의 문제가 NP-Complete로 밝혀졌다.
- **실생활**: 하드웨어 검증, AI 계획 수립, 암호 해독.

### 2-3. Subset Sum

- **문제**: 정수 집합에서 합이 목표값 T가 되는 부분집합이 존재하는가?
- **예시**: `{3, 1, 4, 2, 6}` 에서 합이 `7`인 부분집합 → `{1, 6}` 또는 `{3, 4}`.
- **왜 어렵나**: 부분집합의 수가 2ᴺ개라 N이 크면 전부 시도 불가.
- **실생활**: 예산 배분, 짐 싸기(배낭 문제의 변형), 암호화(knapsack 암호).

## 3. 실전 전략 — NP 문제를 코딩 테스트에서 어떻게 다루는가

> **30초 요약**: NP 문제가 나왔을 때 N의 크기를 먼저 봐라. N이 작으면 완전 탐색, 좀 더 크면 백트래킹+가지치기, 더 크면 비트마스크 DP, 그래도 크면 근사 알고리즘을 쓴다.

NP 문제를 만났을 때 패닉하지 말자. **"N이 얼마나 큰가?"** 를 가장 먼저 확인해라.

```
N ≤ 8       → 브루트 포스 (순열/조합 완전 탐색)
N ≤ 15~20   → 백트래킹 + 가지치기, 또는 비트마스크 DP
N ≤ 20      → 비트마스크 DP (2^N 상태)
N > 20      → 근사/휴리스틱, 또는 다른 관점으로 모델링
```

---

### 3a. 브루트 포스 (Brute Force)

> **30초 요약**: 모든 경우의 수를 전부 시도한다. N이 아주 작을 때(≤ 8 정도)만 쓸 수 있다. N!이 얼마나 빨리 폭발하는지 직접 느껴보자.

#### N! 의 폭발적 증가

| N | N! | 1초에 10⁸ 연산으로 걸리는 시간 |
|---|-----|-------------------------------|
| 8 | 40,320 | 0.0004초 |
| 10 | 3,628,800 | 0.036초 |
| 12 | 479,001,600 | 4.79초 (위험) |
| 15 | 1.3 × 10¹² | 130,000초 (불가) |
| 20 | 2.4 × 10¹⁸ | 우주 나이보다 긴 시간 |

#### C++ 코드

```cpp
// 브루트 포스 TSP — N개 도시의 모든 순열을 시도
// N이 커질수록 N! 이 폭발적으로 증가해 곧 시간 초과가 난다
#include <bits/stdc++.h>
using namespace std;

int main() {
    // 4개 도시 간 거리 행렬 (0-indexed)
    // dist[i][j] = 도시 i -> 도시 j 이동 비용
    const int N = 4;
    int dist[N][N] = {
        { 0, 10, 15, 20 },
        { 10,  0, 35, 25 },
        { 15, 35,  0, 30 },
        { 20, 25, 30,  0 }
    };

    // 도시 0을 시작점으로 고정하고 나머지 순열 탐색
    vector<int> cities = {1, 2, 3};
    int minCost = INT_MAX;

    do {
        // 경로: 0 → cities[0] → cities[1] → ... → 0
        int cost = dist[0][cities[0]];
        for (int i = 0; i + 1 < (int)cities.size(); i++) {
            cost += dist[cities[i]][cities[i + 1]];
        }
        cost += dist[cities.back()][0]; // 출발지 복귀
        minCost = min(minCost, cost);
    } while (next_permutation(cities.begin(), cities.end()));

    cout << "브루트 포스 TSP 최솟값: " << minCost << "\n";
    // N=4 결과: 0->1->3->2->0 = 10+25+30+15 = 80
    return 0;
}
```

#### 시간/공간 복잡도

- 시간: O(N! × N) — N이 12만 넘어도 실질적으로 불가능
- 공간: O(N) — 순열 저장

#### 자주 하는 실수

1. **도시 0 고정을 안 함**: 순환 경로는 시작점을 어디로 잡아도 같은 경로다. 도시 0을 고정하지 않으면 N! 대신 N×(N-1)! 를 탐색하게 되어 N배 더 느려진다.
2. **next_permutation 순서 실수**: `next_permutation`은 현재 순열보다 사전순으로 큰 순열로 이동한다. 반드시 오름차순으로 초기화된 벡터에서 시작해야 모든 순열을 탐색한다.

#### 연습문제

1. [BOJ 10819] 차이를 최대로 — N개(≤ 8) 수의 순열 중 인접한 수의 차이 합이 최대인 경우
2. [BOJ 1759] 암호 만들기 — 조합(next_permutation 또는 재귀)으로 완전 탐색

### 3b. 백트래킹 + 가지치기 (Backtracking + Pruning)

> **30초 요약**: 브루트 포스에 "이 방향은 이미 답이 될 수 없다"는 조기 종료 조건을 추가한다. 최악은 브루트 포스와 같지만 실제로는 훨씬 빠르다.

#### 핵심 아이디어

```
탐색 트리를 DFS로 내려가면서,
현재까지 비용이 이미 알려진 최솟값보다 크면 → 즉시 돌아간다 (가지치기).
```

#### 시각화

```
출발: 0 (비용 0)
├── 1 (비용 10)
│   ├── 2 (비용 45)  ← 이미 현재 최솟값(80) 미만이므로 계속
│   │   └── 3 (비용 75) → 복귀 80 ← 최솟값 갱신
│   └── 3 (비용 35)
│       └── 2 (비용 65) → 복귀 80 ← 같음
├── 2 (비용 15)
│   ├── 1 (비용 50)
│   │   └── 3 (비용 75) → 복귀 95 ← 80보다 크므로 가지치기!
│   └── ...
└── ...
```

#### C++ 코드

```cpp
// 백트래킹 + 가지치기로 TSP 풀기
// 현재까지 누적 비용이 이미 알려진 최솟값보다 크면 탐색 중단(pruning)
#include <bits/stdc++.h>
using namespace std;

const int N = 4;
int dist[N][N] = {
    { 0, 10, 15, 20 },
    { 10,  0, 35, 25 },
    { 15, 35,  0, 30 },
    { 20, 25, 30,  0 }
};

bool visited[N];
int minCost;

// cur      : 현재 도시
// depth    : 방문한 도시 수
// cost     : 지금까지 누적 비용
void backtrack(int cur, int depth, int cost) {
    // 모든 도시 방문 후 출발지(0)로 복귀
    if (depth == N) {
        minCost = min(minCost, cost + dist[cur][0]);
        return;
    }

    for (int next = 0; next < N; next++) {
        if (visited[next]) continue;

        int newCost = cost + dist[cur][next];
        // 가지치기: 이미 현재 최솟값 이상이면 탐색 불필요
        if (newCost >= minCost) continue;

        visited[next] = true;
        backtrack(next, depth + 1, newCost);
        visited[next] = false;
    }
}

int main() {
    minCost = INT_MAX;
    fill(visited, visited + N, false);
    visited[0] = true; // 도시 0 에서 출발

    backtrack(0, 1, 0);

    cout << "백트래킹 TSP 최솟값: " << minCost << "\n"; // 80
    return 0;
}
```

#### 시간/공간 복잡도

- 시간: 최악 O(N!) — 하지만 가지치기 덕분에 실제로는 훨씬 적음
- 공간: O(N) — 재귀 스택 + visited 배열

#### 자주 하는 실수

1. **가지치기 조건에 등호 포함 여부**: `>= minCost`로 해야 같은 비용일 때도 탐색을 건너뛸 수 있다. 단, 경로 복원이 필요하면 `>` 로 바꿔야 할 수 있다.
2. **visited 복원 누락**: `visited[next] = false`를 빠뜨리면 다른 경로에서 그 도시를 방문할 수 없게 된다. 백트래킹의 핵심은 상태를 **원복**하는 것이다.

2. [BOJ 2580] 스도쿠 — 숫자 배치의 백트래킹

### 3c. 비트마스크 DP

> **30초 요약**: 방문한 도시들의 집합을 비트(0/1)로 표현해 DP 상태로 저장한다. N ≤ 20에서 O(N² × 2ᴺ)으로 TSP를 풀 수 있다.

비트마스크 DP는 **"어떤 집합을 방문했는가"** 를 정수 하나로 표현하는 기법이다. 예를 들어 도시가 4개일 때, 도시 0과 2를 방문한 상태는 `0b0101 = 5`로 표현한다.

- `mask | (1 << v)` : mask에 도시 v를 추가
- `(mask >> v) & 1` : mask에서 도시 v가 방문됐는지 확인
- `mask ^ (1 << v)` : mask에서 도시 v를 제거

자세한 구현은 **섹션 4** 에서 풀 코드로 다룬다.

### 3d. 탐욕적 근사 (Greedy Approximation)

> **30초 요약**: 최적해를 포기하고 "충분히 좋은" 답을 빠르게 구한다. Nearest-Neighbor는 항상 가장 가까운 도시로 이동하는 전략이다.

#### 핵심 아이디어

```
현재 위치에서 아직 방문하지 않은 도시 중 가장 가까운 곳으로 이동.
마지막에 출발지로 돌아온다.
```

- **장점**: O(N²)으로 매우 빠르다.
- **단점**: 최적해를 보장하지 않는다. 최악의 경우 최적해보다 수십 배 나쁠 수 있다.
- **언제 쓰나**: N이 커서 정확한 방법이 불가능하거나, 시간 제한이 빡빡할 때 "그냥 제출해봐야 하는" 상황.

> **삼각부등식 주의**: NN의 알려진 근사비 보장(예: 메트릭 TSP에서 Θ(log N))은 거리 행렬이 **삼각부등식** `d(a,c) ≤ d(a,b) + d(b,c)`를 만족할 때에만 성립한다. 본 예제 행렬은 `d(1,2)=35 > d(1,0)+d(0,2)=25`로 삼각부등식을 위배하므로 **이론적 근사비 보장이 없는 휴리스틱**으로만 봐야 한다. 실제 지도/거리에서 오는 행렬은 보통 삼각부등식을 만족한다.

#### C++ 코드

```cpp
// 탐욕적 근사: Nearest-Neighbor Heuristic TSP
// 현재 위치에서 아직 방문하지 않은 도시 중 가장 가까운 곳으로 이동
// 최적해 보장은 안 되지만 빠르게 '괜찮은' 답을 얻는다
#include <bits/stdc++.h>
using namespace std;

int main() {
    const int N = 4;
    // 거리 행렬은 §3a와 §4 (브루트포스/비트마스크 DP)에서 사용한 것과 동일.
    // 같은 입력에서 NN과 최적해를 직접 비교하기 위함.
    int dist[N][N] = {
        { 0, 10, 15, 20 },
        { 10,  0, 35, 25 },
        { 15, 35,  0, 30 },
        { 20, 25, 30,  0 }
    };

    // 시작 도시를 일부러 3으로 둔다. 도시 0에서 출발하면 NN이
    // 우연히 최적해(80)와 같아져 "근사가 항상 최적이다"라는
    // 잘못된 인상을 줄 수 있다. 도시 3에서 출발하면 NN은 95를 내고
    // 최적해 80과 차이가 분명히 보인다.
    int startCity = 3;

    bool visited[N] = {};
    int cur = startCity;
    visited[cur] = true;
    int totalCost = 0;

    cout << "시작 도시: " << startCity << "\n";
    cout << "경로: " << startCity;

    for (int step = 1; step < N; step++) {
        int nearest = -1;
        int nearestDist = INT_MAX;

        // 아직 방문하지 않은 도시 중 가장 가까운 곳 탐색
        for (int next = 0; next < N; next++) {
            if (!visited[next] && dist[cur][next] < nearestDist) {
                nearestDist = dist[cur][next];
                nearest = next;
            }
        }

        visited[nearest] = true;
        totalCost += nearestDist;
        cur = nearest;
        cout << " -> " << nearest;
    }

    // 출발지 복귀
    totalCost += dist[cur][startCity];
    cout << " -> " << startCity << "\n";

    // 비교용 최적해(브루트포스/비트마스크 DP에서 검증된 값)
    const int OPTIMAL = 80;
    cout << "Nearest-Neighbor 근사 비용: " << totalCost << "\n";
    cout << "참고: 최적해 = " << OPTIMAL
         << " → 손해 비율 ≈ "
         << (totalCost - OPTIMAL) * 100.0 / OPTIMAL << "%\n";
    // 기대 출력: NN 근사 비용 95, 최적해 80, 손해 약 18.75%
    return 0;
}
```

#### 시간/공간 복잡도

- 시간: O(N²)
- 공간: O(N)

#### 자주 하는 실수

1. **"근사 = 틀린 답"이 아님**: 근사 알고리즘은 의도적으로 최적을 포기한다. "틀렸다"고 오해하지 말자. 상황에 따라 합리적인 선택이다.
2. **시작 도시에 따라 결과가 달라짐**: Nearest-Neighbor는 어디서 출발하느냐에 따라 경로가 다르다. 여러 시작점을 시도하고 최솟값을 취하는 방법도 있다.

## 4. 비트마스크 DP TSP — N ≤ 20에서 외판원 문제 완전 정복

> **30초 요약**: `dp[mask][last]` = "mask에 포함된 도시들을 방문하고 마지막이 last일 때의 최소 비용". 상태 수가 N × 2ᴺ 개이고, 각 전이가 O(N)이라 전체 O(N² × 2ᴺ). N=20이면 약 4억 연산으로 통상 3~5초 안에 가능하다.

### 일상 비유

도장 스탬프 카드를 생각해보자. 카드에 N개의 칸이 있고, 각 칸에 도장을 찍으면 방문한 것이다. **어떤 칸들에 도장이 찍혀 있고, 가장 마지막에 어느 칸을 찍었냐** — 이 두 가지 정보만 알면 앞으로 남은 최적 경로를 계산할 수 있다. 비트마스크 DP는 "도장 카드 상태"를 숫자 하나(비트마스크)로 표현하는 것이다.

### 비트마스크 기초 복습

```
도시 4개 (0, 1, 2, 3)를 비트로 표현:
도시 0만 방문: 0001 (=1)
도시 0,1 방문: 0011 (=3)
도시 0,2 방문: 0101 (=5)
모두 방문:     1111 (=15)

연산:
mask | (1<<v)    : v를 mask에 추가  (0011 | 0100 = 0111)
(mask >> v) & 1  : v가 mask에 있나? (0011 >> 1 = 0001, & 1 = 1 → 있음)
mask ^ (1<<v)    : v를 mask에서 제거 (0011 ^ 0001 = 0010)
```

### 시각화 — DP 전이 예시 (N=4)

```
상태: dp[0b0011][1] = 10
      (도시 0,1 방문, 마지막=1, 비용=10)
      
다음 도시 2로 이동:
dp[0b0111][2] = min(dp[0b0111][2], dp[0b0011][1] + dist[1][2])
              = min(INF, 10 + 35) = 45

다음 도시 3으로 이동:
dp[0b1011][3] = min(dp[0b1011][3], dp[0b0011][1] + dist[1][3])
              = min(INF, 10 + 25) = 35
```

### C++ 코드 (풀 구현)

```cpp
// 비트마스크 DP로 TSP 풀기 (핵심 예제)
// 상태: dp[mask][last]
//   mask : 지금까지 방문한 도시들의 집합 (비트 표현)
//   last : 마지막으로 방문한 도시
//   값   : 그 상태에서 출발지(0)를 포함해 mask에 속한 도시들을
//          순서대로 방문했을 때의 최소 누적 비용
//
// 점화식:
//   dp[mask | (1<<v)][v] = min(dp[mask | (1<<v)][v],
//                              dp[mask][u] + dist[u][v])
//   (v: mask에 없는 도시, u: 현재 마지막 도시)
//
// 최종 답:
//   min over u of (dp[(1<<N)-1][u] + dist[u][0])
//   즉 모든 도시를 방문한 상태에서 출발지로 돌아오는 최솟값
#include <bits/stdc++.h>
using namespace std;

int main() {
    const int N = 4; // 도시 수 (0 ~ N-1), 0이 출발/도착지

    // 거리 행렬
    int dist[N][N] = {
        { 0, 10, 15, 20 },
        { 10,  0, 35, 25 },
        { 15, 35,  0, 30 },
        { 20, 25, 30,  0 }
    };

    // dp 테이블 초기화: 도달 불가 상태는 매우 큰 값으로
    const int INF = 1e9;
    // dp[mask][last]: mask = 방문한 도시 비트셋, last = 마지막 도시
    vector<vector<int>> dp(1 << N, vector<int>(N, INF));

    // 도시 0 에서 출발: 도시 0만 방문한 상태, 비용 0
    // (1<<0) = 0b0001 → 도시 0 방문 표시
    dp[1 << 0][0] = 0;

    // mask를 0부터 (1<<N)-1 까지 순서대로 확장
    for (int mask = 0; mask < (1 << N); mask++) {
        for (int u = 0; u < N; u++) {
            // dp[mask][u]가 유효한 상태인지 확인
            if (dp[mask][u] == INF) continue;
            // u가 mask에 포함되어 있는지 확인
            // (mask >> u) & 1: mask에서 u번째 비트가 1이면 방문함
            if (!((mask >> u) & 1)) continue;

            // u 에서 아직 방문하지 않은 도시 v로 이동 시도
            for (int v = 0; v < N; v++) {
                // (mask >> v) & 1: 이미 방문했으면 건너뜀
                if ((mask >> v) & 1) continue;

                // 새로운 상태: mask에 v를 추가
                // mask | (1<<v): v번째 비트를 1로 세팅
                int newMask = mask | (1 << v);
                int newCost = dp[mask][u] + dist[u][v];

                // 더 작은 비용이면 갱신
                if (newCost < dp[newMask][v]) {
                    dp[newMask][v] = newCost;
                }
            }
        }
    }

    // 모든 도시를 방문한 상태: (1<<N) - 1 = 0b1111
    int fullMask = (1 << N) - 1;
    int answer = INF;

    // 마지막 도시 u에서 출발지(0)로 돌아오는 최솟값 탐색
    for (int u = 0; u < N; u++) {
        if (dp[fullMask][u] == INF) continue;
        answer = min(answer, dp[fullMask][u] + dist[u][0]);
    }

    cout << "비트마스크 DP TSP 최솟값: " << answer << "\n"; // 80

    // ------- 경로 역추적 (선택) -------
    // 마지막 도시 찾기
    int last = -1;
    for (int u = 0; u < N; u++) {
        if (dp[fullMask][u] + dist[u][0] == answer) {
            last = u;
            break;
        }
    }

    // 역방향으로 경로 복원
    vector<int> path;
    int mask = fullMask;
    int cur = last;
    while (cur != 0 || mask != (1 << 0)) {
        path.push_back(cur);
        // cur 이전에 어디서 왔는지 탐색
        int prevMask = mask ^ (1 << cur); // mask에서 cur 제거
        for (int prev = 0; prev < N; prev++) {
            if (!((prevMask >> prev) & 1)) continue;
            if (dp[prevMask][prev] + dist[prev][cur] == dp[mask][cur]) {
                mask = prevMask;
                cur = prev;
                break;
            }
        }
    }
    path.push_back(0); // 출발지 추가
    reverse(path.begin(), path.end());
    path.push_back(0); // 도착지(복귀) 추가

    cout << "최적 경로: ";
    for (int i = 0; i < (int)path.size(); i++) {
        if (i) cout << " -> ";
        cout << path[i];
    }
    cout << "\n";

    return 0;
}
```

### 코드 흐름 요약

```
1. dp[1][0] = 0  (도시 0만 방문, 비용 0)

2. 모든 (mask, u) 쌍에 대해:
   └─ u가 mask에 있고, dp[mask][u]가 유효하면
      └─ mask에 없는 모든 v에 대해
         └─ dp[mask|(1<<v)][v] 갱신

3. fullMask = (1<<N)-1
   answer = min(dp[fullMask][u] + dist[u][0]) for all u
```

### 시간/공간 복잡도

| 항목 | 복잡도 | N=20 기준 |
|------|--------|-----------|
| 시간 | O(N² × 2ᴺ) | 약 4억 연산 |
| 공간 | O(N × 2ᴺ) | 약 2천만 int = 80MB |

> N=20이면 메모리가 빠듯할 수 있다. `int` 대신 `short`를 쓰거나, 거리 값이 작으면 메모리를 아낄 수 있다.

### 자주 하는 실수

1. **dp 초기화를 INT_MAX로 하면 오버플로우**: `dp[mask][u] + dist[u][v]`에서 INT_MAX + 양수가 음수로 오버플로우된다. `1e9`나 `0x3f3f3f3f`처럼 더해도 안전한 값으로 초기화해야 한다.
2. **`(mask >> u) & 1` 조건 누락**: u가 mask에 포함되지 않은 상태를 전이 출발점으로 쓰면 잘못된 경로가 만들어진다. 반드시 확인해야 한다.
3. **fullMask 계산 실수**: `(1 << N) - 1`이 올바르다. `N = 20`이면 `1 << 20 = 1048576`, fullMask = 1048575.
4. **경로 복원 시 무한 루프**: 역추적 중 `prev`를 못 찾으면 `cur`와 `mask`가 갱신되지 않아 무한 루프에 빠진다. 디버깅할 때는 `assert`나 카운터를 추가하자.

| 5 | 비트마스크 DP의 핵심: `dp[mask][last]`, 상태 수 N × 2ᴺ |
| 6 | 근사 알고리즘은 "틀린 답"이 아니라 "의도적으로 타협한 답"이다 |

> 마지막으로 한마디 — 이 내용이 한 번에 다 이해되지 않아도 전혀 괜찮다. 비트마스크 DP는 처음에는 누구나 어렵다. 섹션 4의 코드를 직접 손으로 따라 치면서, `mask = 0b0101`일 때 어떤 값이 들어가는지 종이에 적어보자. 그게 가장 빠른 이해 방법이다. 고등학생이 이걸 다 자유자재로 쓸 필요는 없다 — 감을 잡았다면 이번 주는 성공이다.
